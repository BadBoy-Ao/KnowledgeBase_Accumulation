# Prompt Engineering的发展历程

​	提示词工程（Prompt Engineering）是一门较新的学科，关注提示词开发和优化，帮助用户将 LLM 用于各场景和研究领域。掌握了提示词工程相关技能将有助于用户更好地了解 LLM 的能力和局限性。

​	但提示词并不是近年来才有的概念。实际上，从计算机技术的初步发展阶段，提示词就已经存在了。在早期的计算机界面中，用户需要通过键入特定的命令行提示词来与计算机进行交互。随着技术的发展，图形用户界面（GUI）成为主流，但提示词仍然在某些领域，如编程和高级系统管理中发挥着关键作用。

​	研究人员可利用 Prompt Engineering 来提升 LLM 处理复杂任务场景的能力，如问答和算术推理能力。开发人员可通过设计 Prompt、研发强大的工程技术，来实现和 LLM 或 其他生态工具的高效接轨。

​	Prompt Engineering 不仅仅是关于设计和研发 Prompt。它包含了与 LLM 交互和研发的各种技能和技术。Prompt Engineering 在实现和 LLM 交互、对接，以及理解 LLM 能力方面都起着重要的作用。用户可以通过 Prompt Engineering 来提高 LLM 的安全性，也可以赋能 LLM，比如借助专业领域知识和外部工具来增强 LLM 能力。

# Prompt Engineering Framework

## 定义

​	Prompt 工程框架是**一套标准化的Prompt设计流程或模板**，它规定了：

- Prompt的**结构**（如“角色 - 任务 - 示例 - 约束”）；
- 解决问题的**步骤**（如“先分解任务，再逐步推理”）；
- 优化的**方法**（如“收集反馈-调整Prompt-验证效果”）；

​	***核心作用：***

1. **标准化**：让 Prompt 设计有章可循，避免随意性；
2. **可复用**：将通用部分（如角色设定、约束条件）做成模板，减少重复劳动；
3. **可优化**：通过框架中的“反馈环节”，持续提升 Prompt 效果；
4. **可解释**：框架中的每一步都有明确的目的，方便团队协作（例如产品和算法一起调整 Prompt）；

## LLM 模型参数 设置

​	使用 Prompt 时，通常会通过 API 或直接与 LLM 进行交互。同时也可以通过配置一些参数来获得不同的提示结果。调整这些设置对于提高响应的可靠性非常重要，以下是使用不同 LLM 的 API 或者设计时会遇到较为常见的设置：

### `Temperature`

​	简单来说，`temperature`的参数值越小，模型就会返回越确定的一个结果。如果调高该参数值，LLM 可能会返回更随机的结果，也就是说这可能会带来更多样化或更具创造性的产出。

- 调小`temperature`：实质是在减少其他可能的 `token` 的权重。
- 在实际应用方面，对于质量保障(例如 QA)等任务，可以设置更低的`temperature`值，以促使模型基于事实返回更真实和简洁的结果。对于诗歌生成或其他创造性任务，适度地调高`temperature`参数值可能会更好。

### `Top_p`

​	同样，使用`top_p`(与`temperature`一起称为核采样[nucleus sampling]技术)，可以用来控制模型返回结果的确定性。如果你需要准确和事实的答案，就把参数值调低。如果你在寻找更多样化的响应，可以将该值调高；

- 使用 `Top_p` 意味着只有词元集合`tokens`中概率从最大开始求和直到第一次 >= `top_p`的才会被考虑用于响应。因此，较低的`top_p`值会选择较少的且有最大概率的响应。同时，较高的 `top_p` 值将使模型考虑更多可能性的词语，也会囊括不太可能的词语，从而导致更多样化的输出。
- ***建议***：只改变 `temperature` 和 `Top P` 其中一个参数即可。

### `Max Length`

​	可以通过调整`max length` 来控制大模型生成的 token 数。指定 Max Length 有助于防止 LLM 生成冗长或不相关的响应并控制成本。

### `Stop Sequences`

​	`stop sequences`是一个字符串，可以阻止模型生成 token。指定 `stop sequences`是控制 LLM 响应长度和结构的另一种方法。

- 其核心作用是：当模型生成的内容中出现预设的字符串时，立即停止生成，从而精准控制输出的截止点【例如，让模型在生成“###”时停止，确保输出在固定标记前结束】
- `stop sequence` 的有效性完全依赖于它是否会在目标截止点被模型自然生成，需要与输出格式严格匹配。

### `Frequency Penalty`

​	`frequency penalty`是对下一个生成的 token 进行惩罚，这个惩罚和 token 在响应和提示中已出现的次数成比例。`frequency penalty`越高，某个词再次出现的可能性越小。

- 这个设置通过给 重复数量多的 token 设置更高的惩罚来减少响应中单词的重复。

### `Presence Penalty`

​	`presence penalty`也是对重复 token 施加惩罚，但与 `frequency penalty` 不同的是，惩罚对于所有重复的 token 都是相同的。【出现两次的 token 和出现 10 次的 token 会受到相同的惩罚】

- 这个设置可以防止模型在响应中过于频繁地生成重复的词。
- 如果希望模型生成多样性或创造性的文本，可以设置更高的`presence penalty` ；如果希望模型生成更专注的内容，可以设置更低的`presence penalty`。
- ***建议***：只改变 `frequency penalty` 和`presence penalty`其中一个参数即可。

## 基本概念

### **提示词工程**

​	设计有效的提示词以指导模型执行期望任务的方法；

### **零样本提示 zero-shot prompting** 

 	直接将 *问题* 给 LLM，让 LLM 给出回答，而没有提供任何关于你希望它完成的任务的示例或者示范。

​	一些 LLM 具备进行 零样本提示能力，但这取决于手头任务的复杂性和知识，以及在模型上被训练的数据上所表现良好的任务。

### **少样本提示 few-shot prompting**

​	带着 *示例* 的问题，询问 LLM。

## Prompt 基本元素

​	普遍的 Prompt 可以包含如下元素：

- 指令`Instruction`：你想要模型执行的一个特定的任务或者指令；
- 上下文`Content`：能够引导模型更好回复的外部信息或者额外的上下文文本；
- 输入数据`Input Data`：用户的问题；
- 输出指标`Output Indicator`：输出的类别或格式；

# Prompt 常用框架

## CO-STAR 框架

### 整体框架：

- C (Context) : 上下文
- O (Objective) : 目标
- S (Style) : 风格
- T (Tone) : 语气
- A (Audience) : 受众
- R (Response) : 回复

### 使用场景

1. 工作汇报报告：基于工作场景，需要向上汇报，或者是基于一些项目情况做工作汇报。

```markdown
**[C] Content(上下文): **
我需要撰写一份专业的工作汇报或方案。我希望您首先扮演一名专业的顾问，通过结构化提问来协助我收集和梳理所有必要的信息，然后利用这些信息为我撰写内容。

**[O]Object(目标): **
您的核心目标是执行一个两步流程：
1. **第一步（信息收集）：** 作为您的第一步回复，您必须向我提出一系列关键问题，以收集撰写报告所需的所有背景。
2. **第二步（内容生成）：** 在我回答了您的问题后，你将利用我提供的所有信息，生成一份逻辑严谨、高质量的报告/初稿。

**[S]Style(风格): **
采用高级商业分析师和专业报告撰写顾问的风格。提问应精准、专业、撰写时应结构清晰、书面化。

**[T]Tone(语气): **
专业、有条理、循循善诱、专家感、乐于助人。

**[A]Audience(受众): **
在第一步中，您的受众是我。
在第二步中，生成的报告/方案的受众将由我的回答决定（例如我的上司、客户等）。

**[R]Response(响应要求): **
您的**第一个回复**绝对**不能**是报告模板或正文。
您的第一个回复**必须**只包含以下5个关键问题：

1. **您的角色：** 您当前的具体职位或角色是什么？
2. **报告类型：** 您需要撰写什么类型的报告或方案？（例如：项目总结、季度汇报、新方案提议、可行性分析等）
3. **目标受众：** 这份报告/方案的主要阅读者是谁？（例如：直属上司、管理层、客户、跨部门同事）
4. **核心内容：** 您希望报告/方案中必须包含哪些关键要点、数据或部分？
5. **核心目的：** 您希望通过这份报告/方案达到什么主要目的？（例如：获得批准、信息同步、决策支持）

*请在我完整回答这些问题后，再开始执行第二步（撰写报告）。*
```

## APE (Action Purpose Except)提示词框架

​	APE 框架提倡将用户的请求分解为三个主要部分：行动、目的和期望。

- **行动（Action）**：定义需要完成的特定任务、行动或活动。这是框架的第一步，旨在明确要执行的具体任务或活动；
- **目的（Purpose）**：讨论意图或目标。这部分是为了解释为什么要执行这个特定的任务或活动，它背后的意图是什么，以及它将如何支持更大的目的或目标；
- **期望（Expectation）**：陈述期望的结果。在最后一步，明确表述通过执行特定任务或活动期望实现的具体结果或目标。

```markdown
# 例：
# 假设你是一家产品销售公司的营销经理，你想通过社交媒体广告来提高产品的在线销售。按照 APE（行动，目的，期望）框架，你可以创建以下 Prompt：

1. 行动（Action）：准备发布一系列的社交媒体广告，宣传我们的最新产品；
2. 目的（Purpose）：通过吸引社交媒体用户的注意，提高产品的在线销售和品牌知名度；
3. 期望（Expectation）：在接下来的一个月中，通过社交媒体广告，在线销售增加 30%，并且我们的品牌在社交媒体上的关注度提高 20%。
```

## BROKE 提示词框架

​	陈财猫老师的 BROKE 框架融合了 OKR（Objective and Key Results）方法论，旨在通过结构化的方法来提升 GPT 的设计提示，提高工作效率和质量。它不仅仅是一个静态的框架，而是一个动态的过程，通过不断的测试和调整，来优化提示的设计和输出。

​	通过应用 BROKE 框架，可以创建结构化和明确的 GPT 提示，从而更有效地达成目标，提高工作效率和质量。同时，通过不断的评估和调整，可以确保持续的进步和优化，从而形成一个正向的循环，不断地推动自己向前。

- **背景（Background）**：提供足够的背景信息，使 GPT 能够理解问题的上下文；
- **角色（Role）**：设定特定的角色，让 GPT 能够根据该角色来生成响应；
- **目标（Objectives）**：明确任务目标，让 GPT 清楚知道需要实现什么；
- **关键结果（Key Results）**：定义关键的、可衡量的结果，以便让 GPT 知道如何衡量目标的完成情况；
- **演变（Evolve）**：通过试验和调整来测试结果，并根据需要进行优化；

```markdown
# 应用 BROKE 框架的提示实例，主题是“如何提高编程技能”：
# BROKE 框架实例

**_Background：_** 编程是一种重要的技能，能够帮助解决各种问题。随着技术的快速发展，不断地学习和提高编程技能变得至关重要；
**_Role：_**假设你是一名经验丰富的编程导师，能提供实用的建议和指导；
**_Objectives：_**
- _了解编程基础和核心概念_
- _通过实际项目实践和提高编程技能_
- _接受同行和导师的反馈，了解进步和需要改进的地方_
**Key Results：_**
- _完成至少 5 个不同类型的编程项目_
- _每个项目后都能获得专业的反馈和建议_
- _至少阅读和总结 10 篇关于编程最佳实践和新技术的文章_
**_Evolve：_**
- _每个月评估一次学习进度，调整学习计划_
- _根据项目实践和反馈来调整学习资源和方法_
- _如果发现某个学习资源或方法不再有效，寻找新的替代方案_
```

## CHAT 提示词框架

​	CHAT 框架集中于角色、背景、目标和任务四个核心部分，为用户与大模型的深度交互提供了全面的指导。这种交互策略使得LLM能够更准确、更有针对性地为用户提供所需的答案和资源。

- **角色（Character）**：角色为大模型提供了关于用户身份和角色的信息，有助于大模型更好地定制其回应。
- **背景（History）**：背景部分提供了与当前问题相关的历史信息和背景知识。这使得大模型能够更好地了解了用户所在的上下文环境。
- **目标（Ambition）**：目标描述了用户希望从与大模型的交互中实现的长期或短期目标。它可以帮助大模型提供更优针对性的建议和解决方案。
- **任务（Task）**：任务部分明确了用户希望大模型执行的具体任务或行动。这是最直接的指导，告诉大模型用户期望的具体操作或回答。

```markdown
**_用户：_**我是一名历史教师，想知道关于古罗马的教学资源。
<!-- 大模型提示词框架 -->
**_角色：_**历史教师
**_背景：_**需要教授古罗马历史
**_目标：_**寻找高质量的教学资源
**_任务：_**提供古罗马的教学资源或推荐
```

## CRISPE 提示词框架

​	CRISPE 是由 Matt Nigh 创建，它提供了结构和清晰度，将提示创建过程分解为明确和不同的步骤。此框架有助于确保创建和提示具有明确的目的和结构，从而使 LLM 能够更有效地理解和回应用户的请求。

- **能力和角色（Capacity and Role）：**定义 LLM 应扮演的角色以及能力；
- **洞察（Insight）：**提供有关请求的幕后洞察、背景和上下文；
- **声明（Statement）：**说明您要求的 LLM 完成的任务；

- **个性（Personality）：**定义您希望 LLM 回应时采用的风格、个性或方式；
- **实验（Experiment）：**要求 LLM 为您提供多个示例；

```markdown
**_能力和角色_**: 作为软件开发方面的专家，讨论机器学习框架的主题，并作为专家博客作者
**_洞察_**: 此博客的受众是对学习最新机器学习进展感兴趣的技术专业人员
**_声明_**: 提供对最流行的机器学习框架的全面概述，包括它们的优势和劣势。包括真实的示例和案例研究，以说明这些框架如何在各种行业中的成功应用
**_个性_**: 在回应时，请混合使用 Andrej Karpathy, Francois Chollet, Jeremy Howard 和 Yann LeCun 的写作风格。 
**_实验_**: 给我多个不同的示例。
```
